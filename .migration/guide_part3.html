۸) مدیریت خطاها: فایل api_exception.dart

این کلاس متن خطای انگلیسی سرور را به پیام فارسی دوستانه تبدیل می‌کند. متن‌های خطای PocketBase با متن‌های Supabase فرق دارند، پس نگاشت‌ها عوض شدند.

قدیم

ApiException(this.code, this.message, {this.response}) {
  if (code != 400) return;
  if (message == 'Failed to authenticate.') {                       // PocketBase
    message = 'نام کاربری یا رمز عبور اشتباه است';
  }
  if (message == 'Failed to create record.') {                     // PocketBase
    if (response?.data['data']['username'] != null) {
      if (response?.data['data']['username']['message'] ==
          'The username is invalid or already in use.') {
        message = 'نام‌کاربری نامعتبر است یا قبلا گرفته شده';
      }
    }
  }
}

جدید

ApiException(this.code, this.message, {this.response}) {
  if (code == 400) {
    if (message == 'Invalid login credentials') {      // Supabase: رمز/ایمیل غلط
      message = 'نام کاربری یا رمز عبور اشتباه است';
    }
    if (message == 'User already registered') {      // Supabase: تکراری بودن
      message = 'نام‌کاربری نامعتبر است یا قبلا گرفته شده';
    }
  }
  if (code == 422) {                                       // Supabase: اعتبارسنجی
    if (message == 'Validation failed') {
      message = 'نام‌کاربری نامعتبر است یا قبلا گرفته شده';
    }
  }
}
💡 چرا کد کوتاه‌تر شد؟
PocketBase خطای یوزرنیم تکراری را داخل ساختار تودرتو (data.username.message) می‌فرستاد که باید باز می‌شد. Supabase با پیام سادهٔ "User already registered" جواب می‌دهد؛ علاوه بر آن، در دیتاسورس احراز هویت خودمان هم عبارت already been registered را جداگانه به پیام فارسی «این نام کاربری قبلا ثبت شده است» ترجمه می‌کنیم — یعنی دو لایهٔ ترجمهٔ خطا داریم.

۱۱) خطاهای رایج دانشجویان و راه‌حل آن‌ها

خطا / علامتعلتراه‌حل
401 در همهٔ درخواست‌ها هدر apikey فرستاده نشده در DioProvider هدر apikey: SupabaseConfig.anonKey اضافه کنید (بخش ۳)
PGRST301: Empty JWT is sent ارسال Authorization: Bearer خالی وقتی لاگین نیستید اینترسپتور بخش ۳ را کپی کنید که هدر خالی را حذف می‌کند
PGRST106: Invalid schema فرستادن هدر Accept-Profile: shop هیچ! جداول از طریق ویوهای public در دسترس‌اند؛ پروفایل پیش‌فرض همان public است
type 'Null' is not a subtype of String فیلد NULL در دیتابیس = کلید غایب در JSON در fromJson از ?? defaultValue استفاده کنید (بخش ۵.۴)
type 'String' is not a subtype of List همچنان data['items'] خوانده می‌شود data as List بنویسید — Supabase آرایهٔ خام برمی‌گرداند
لیست خالی برمی‌گردد ولی 200 است فراموشی select=* یا غلط املایی در نام فیلتر URL را در مرورگر/Postman امتحان کنید؛ الگو: table?select=*&field=eq.value
تصاویر لود نمی‌شوند همچنان URL قدیمی ساخته می‌شود خط‌های ساخت URL در مدل‌ها حذف شوند؛ مقدار دیتابیس خودش URL کامل است
Unable to validate email address در ثبت‌نام دامنهٔ غلط مثل apple_shop.local فقط appleshop.local (بدون آندرلاین)
«نام کاربری قبلا ثبت شده» برای کاربر قدیمی رفتار طبیعی — پروفایل قدیمی هست، رمز منتقل نشده کاربر باید با همان یوزرنیم ثبت‌نام مجدد کند (بخش ۴)
403 در ارسال کامنت عدم تطابق توکن و user_id یا عدم لاگین ابتدا login کنید؛ user_id باید همان شناسهٔ کاربر لاگین‌شده باشد
پس از لاگین دوباره 401 می‌گیرید توکن در SharedPreferences ذخیره نشده یا خوانده نشده AuthManager.saveToken را بعد از پاسخ فراخوانی کنید؛ DioProvider همان‌جا می‌خواندش
دیتای واریانت‌ها به‌هم ریخته جای type_id و product_id عوض شده در پارس model و URL را با بخش ۶.۵ مقایسه کنید
