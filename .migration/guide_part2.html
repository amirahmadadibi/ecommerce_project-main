💡 چرا ?? (null-safety) اضافه شد؟
PocketBase برای هر رکورد همهٔ فیلدها را برمی‌گرداند (حتی خالی). PostgREST/Supabase اگر مقدار فیلد در دیتابیس NULL باشد، اصلاً آن کلید را در JSON نمی‌فرستد. اگر بدون ?? بخوانیم، در Dart مقدار null به String غیر nullable می‌رسد و برنامه کرش می‌کند. پس الگوی امن: jsonObject['field'] ?? مقدارپیش‌فرض

factory Comment.fromMapJson(Map<String, dynamic> jsonObject) {
  final user = jsonObject['user'];              // ① رابطه جاسازی‌شده
  final Map<String, dynamic> userMap =
      user is Map<String, dynamic> ? user : const {};  // ② محافظ نوع
  return Comment(
    jsonObject['id'],
    jsonObject['text'],
    jsonObject['product_id'],
    jsonObject['user_id'],
    userMap['avatar'] ?? '',               // ③ آواتار = URL یا خالی
    (userMap['name'] ?? '').isNotEmpty          // ④ اگر name خالی بود،
        ? userMap['name']                          //    username را نشان بده
        : (userMap['username'] ?? ''),
    userMap['avatar'] ?? '',
  );
}
💡 چرا این‌قدر محافظت؟
در دادهٔ قدیمی خیلی از کاربران فیلد name خالی داشتند (فقط username داشتند). کد قدیم برای این کاربرها نام خالی نشان می‌داد. کد جدید اول name را چک می‌کند و اگر خالی بود username را نشان می‌دهد — یعنی هم محکم‌تر است و هم نمایش بهتر شد.

// ─── قدیم: expand پاک‌بیس (کاربرِ کامنت داخل پاسخ باز می‌شد) ───
Map<String, dynamic> qParams = {
  'filter': 'product_id="$productId"',
  'expand': 'user_id',         // ❌ مفهوم PocketBase
  'perPage': 100,
};

return respones.data['items']...

// ─── جدید: embed تابع PostgREST ───
var respones = await _dio.get(
    'rest/v1/comment?select=id,text,user_id,product_id,user:users(id,username,name,avatar)' // ①
    '&product_id=eq.$productId'                                                // ②
    '&order=created_at.desc&limit=100');                                      // ③
return (respones.data as List)
    .map<Comment>((j) => Comment.fromMapJson(j)).toList();
💡 توضیح سه بخش URL جدید کامنت‌ها
① select با embed: user:users(id,username,name,avatar) یعنی «به‌علاوهٔ فیلدهای کامنت، رکورد کاربرِ مرتبط را از جدول users با این چهار فیلد جاسازی کن و با کلید user بده». معادل کاملِ expand=user_id قدیم.
② فیلتر: همان الگوی eq. روی product_id.
③ ترتیب و محدودیت: جدیدترین‌ها اول (order=created_at.desc) و حداکثر ۱۰۰ مورد — در قدیم perPage=100 بود ولی ترتیب پیش‌فرض قدیمی‌ها اول بود؛ این یک بهبود کوچک اختیاری است.
